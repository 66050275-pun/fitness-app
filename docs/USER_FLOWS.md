# NutriAI — User Flow Design

วันที่ 16 กันยายน 2026 • แบบเสนอสำหรับออกแบบและพัฒนา ไม่ใช่สถานะระบบที่เสร็จแล้ว

อ้างอิง: [Figma — What is a user flow?](https://www.figma.com/resource-library/user-flow/)
ใช้หลักหนึ่งเป้าหมายต่อ flow พร้อมจุดเริ่ม การกระทำ ทางเลือก และผลลัพธ์ที่ชัดเจน

กลุ่มผู้ใช้สมมติ: คนที่ต้องการดูแลการกินในชีวิตประจำวันและบันทึกได้รวดเร็ว ต้องทดสอบกับผู้ใช้จริงต่อ

สัญลักษณ์: มุมมน = เริ่ม/จบ, กล่อง = หน้าจอหรือการกระทำ, ข้าวหลามตัด = ตัดสินใจ, เส้นประ = ส่วนต่อยอดที่วางแผนไว้
โครงหลักอิงหน้าจอในโปรเจกต์ ส่วน F02–F05 เป็นฟีเจอร์ใหม่; ไอเดีย N01–N05 ยังไม่รวมในขอบเขตนี้

## 1. ภาพรวมเส้นทางหลัก

```mermaid
flowchart TD
  A([เปิด NutriAI]) --> B{ตั้งค่าเริ่มต้นแล้ว?}
  B -->|ยัง| C[ต้อนรับ → เป้าหมาย → ข้อมูลส่วนตัว]
  C --> D[กิจกรรม → ตรวจเป้าหมาย → รูปภาพหรือข้าม]
  D --> H[Home · สรุปวันนี้]
  B -->|แล้ว| H
  H --> Q[กด + เพิ่มรายการ]
  Q --> L[ค้นหา / Quick Log / สแกนอาหาร]
  L --> R[ตรวจรายการและปริมาณ]
  R --> S([ยืนยันบันทึก → Diary])
  H --> I[Insights · ดูแนวโน้ม]
  H --> K[AI Coach · ขอคำแนะนำ]
  H --> P[โปรไฟล์ · แก้ข้อมูลและเป้าหมาย]
  H --> F[Fitness · เลือกและบันทึกการออกกำลัง]
  Q -.-> V[ใหม่ · F03 บันทึกด้วยเสียง]
  H -.-> M[ใหม่ · F02 สแกนเมนูตามเป้าหมาย]
  K -.-> M
  V -.-> R
  M -.-> ME([เลือกเมนูที่จะสั่ง])
  I -.-> W[ใหม่ · F04 Weekly Story]
  K -.-> X[ใหม่ · F05 วันนี้แผนเปลี่ยน]
  H -.-> X
```

คงแถบหลัก Home / Diary / + / Insights / AI Coach ส่วน Fitness และ Profile เป็นเส้นทางรองจาก Home ตามแบบนี้ ไม่เพิ่มแท็บเพื่อรองรับทุกฟีเจอร์ สแกนอาหารเดิมยังมีส่วนต้นแบบ

## 2. บันทึกอาหาร — เส้นทางร่วม

เป้าหมาย: บันทึกสิ่งที่กินได้ถูกวัน ถูกมื้อ และตรวจแก้ได้

```mermaid
flowchart TD
  A([Home หรือ Diary → กด +]) --> B[เลือกวิธีเพิ่มอาหาร]
  B --> C[ค้นหา / กรอกเอง / สแกน]
  C --> D{พบรายการที่ใช้ได้?}
  D -->|ไม่พบ| E[แก้คำค้น หรือสร้างอาหารเอง]
  E --> C
  D -->|พบ| R[ตรวจอาหาร ปริมาณ วัน และมื้อ]
  R --> F{ข้อมูลถูกต้อง?}
  F -->|ยัง| R
  F -->|ถูกต้อง| G[กดยืนยันบันทึก]
  G --> J{บันทึกสำเร็จ?}
  J -->|ไม่สำเร็จ| T[เก็บข้อมูลที่กรอก ให้ลองใหม่]
  T --> G
  J -->|สำเร็จ| H([Diary แสดงมื้อใหม่และยอดรวม])
  R -->|ยกเลิก| Z([กลับหน้าต้นทางโดยไม่บันทึก])
```

## 3. F02 — สแกนเมนูร้านเพื่อช่วยเลือกตามเป้าหมาย [ใหม่]

เป้าหมาย: ช่วยเลือกเมนูที่น่าจะเหมาะกับการลดไขมัน เพิ่มกล้ามเนื้อ หรือเป้าหมายที่ผู้ใช้เลือก จบเมื่อได้เมนูที่จะสั่ง ไม่มีขั้นบันทึกแคลอรีหรือถ่ายอาหารซ้ำ

```mermaid
flowchart TD
  A([Home หรือ AI Coach → สแกนเมนูร้าน]) --> B[ถ่ายภาพ / เลือกรูป / พิมพ์เมนู]
  B --> C{มีภาพที่อ่านได้?}
  C -->|มี| D[อ่านชื่อและรายละเอียดเมนู]
  D --> E{อ่านสำเร็จ?}
  E -->|สำเร็จ| F[ตรวจและแก้ข้อมูลเมนู]
  E -->|ไม่สำเร็จ| G[ลองใหม่หรือพิมพ์เอง]
  C -->|ไม่มี / ไม่อนุญาตกล้อง| G
  G --> F
  F --> H[ใช้เป้าหมายเดิมหรือเลือกสำหรับครั้งนี้]
  H --> I{ข้อมูลพอแนะนำหรือไม่?}
  I -->|พอ| J[ดู 2–3 ตัวเลือก พร้อมเหตุผลและข้อจำกัด]
  I -->|ไม่พอ| L[แจ้งข้อจำกัดและให้เพิ่มรายละเอียด]
  L -->|เพิ่มข้อมูล| F
  L -->|จบ| N([กลับต้นทาง])
  J -->|เลือก| K([ได้เมนูที่จะสั่ง])
  J -->|เปลี่ยนเป้าหมาย| H
```

คำแนะนำอิงข้อมูลที่อ่านได้และข้อมูลประกอบที่ตรวจสอบได้ ไม่ฟันธงโปรตีนสูงหรือไขมันต่ำจากภาพอย่างเดียว หากรองรับได้ไม่ถึง 2–3 เมนูให้เสนอเฉพาะที่มีข้อมูล ไม่มีการประมาณน้ำหนักหรือสร้างตัวเลขแคลอรีใน flow นี้ ไม่เพิ่มรายการใน Diary ไม่ต้องยืนยันว่ากินแล้ว ผู้ใช้ยกเลิกกลับต้นทางได้ทุกขั้น การเปลี่ยนเป้าหมายครั้งนี้ไม่แก้เป้าหมายหลัก

## 4. F03 — บันทึกด้วยเสียง [ใหม่]

เป้าหมาย: พูดหนึ่งครั้งแล้วตรวจรายการทั้งหมดก่อนบันทึก

```mermaid
flowchart TD
  A([กด + → บันทึกด้วยเสียง]) --> B{ไมค์พร้อมและอนุญาต?}
  B -->|ไม่พร้อม| C[พิมพ์สิ่งที่กินแทน]
  B -->|พร้อม| D[กดเริ่มพูด → หยุดเมื่อพูดจบ]
  D --> E{ได้ข้อความ?}
  E -->|ไม่ได้| F[พูดใหม่หรือเลือกพิมพ์]
  F --> C
  F --> D
  E -->|ได้| G[ตรวจและแก้ข้อความ]
  C --> G
  G --> H[แยกเป็นรายการอาหาร]
  H --> I{อาหารหรือปริมาณไม่ชัด?}
  I -->|ใช่| J[เลือกอาหารและระบุปริมาณเพิ่ม]
  J --> K[ตรวจทุกรายการ พร้อมวันและมื้อ]
  I -->|ไม่| K
  K -->|แก้หรือลบรายการ| K
  K -->|ยืนยัน| L([เข้าสู่ขั้นยืนยันบันทึกร่วม])
  K -->|ยกเลิก| M([กลับต้นทางโดยไม่บันทึก])
```

หยุดไมค์เมื่อออกจากหน้า ไม่เริ่มฟังเอง เมื่อแยกข้อความไม่ได้ให้กรอกผ่าน Quick Log ได้ ป้องกันการบันทึกซ้ำจากการกดยืนยันหลายครั้ง

## 5. F04 — Weekly Story [ใหม่]

เป้าหมาย: เข้าใจสิ่งที่เกิดขึ้นในสัปดาห์และเลือกสิ่งเล็ก ๆ ที่จะลองต่อ

```mermaid
flowchart TD
  A([Insights → Weekly Story]) --> B[แสดงช่วง 7 วันและจำนวนวันที่บันทึก]
  B --> C{มีข้อมูลหรือไม่?}
  C -->|ไม่มี| D[ชวนเริ่มบันทึกมื้อแรก]
  D --> E([ไปเพิ่มอาหาร])
  C -->|มี| F[สิ่งที่ทำได้ดีจากข้อมูลจริง]
  F --> G{ข้อมูลพอให้สรุปรูปแบบ?}
  G -->|ไม่พอ| H[แจ้งว่ายังสรุปรูปแบบไม่ได้]
  G -->|พอ| I[สิ่งที่สังเกตได้ พร้อมข้อมูลอ้างอิง]
  H --> J[เสนอสิ่งที่ลองต่อหนึ่งอย่าง]
  I --> J
  I -->|ดูรายละเอียด| K[ดูบันทึกที่ใช้สรุป]
  K --> I
  J --> L{อยากลองหรือไม่?}
  L -->|อยากลอง| M([เก็บสิ่งที่จะลองไว้ดูต่อ])
  L -->|ไว้ก่อน| N([กลับ Insights])
```

เกณฑ์ข้อมูลเพียงพอเป็นกฎที่ต้องกำหนดและทดสอบรายข้อสังเกต ไม่ใช้วันว่างเป็นศูนย์ ไม่สรุปเหตุและผล เป้าหมายที่เลือกเป็นกิจกรรมสมัครใจ ไม่แก้เป้าหมายสารอาหารอัตโนมัติ

## 6. F05 — วันนี้แผนเปลี่ยน [ใหม่]

เป้าหมาย: ได้คำแนะนำที่เข้ากับสถานการณ์วันนี้โดยไม่รู้สึกผิด

```mermaid
flowchart TD
  A([Home หรือ AI Coach]) --> B[กด วันนี้แผนเปลี่ยน]
  B --> C[เลือกวันที่และบริบท]
  C --> D[กินเลี้ยง / เดินทาง / ไม่มีเวลาทำอาหาร]
  D --> E[ดูคำแนะนำสั้นตามสถานการณ์]
  E --> F{ใช้บริบทนี้?}
  F -->|เปลี่ยน| C
  F -->|ยกเลิก| G([กลับต้นทาง])
  F -->|ใช้| H[เก็บบริบทของวันที่เลือก]
  H --> I([Home แสดงคำแนะนำของวันนั้น])
  I -->|แก้บริบท| C
  I -->|กลับวันปกติ| J[ล้างบริบทวันนั้น]
  J --> G
```

วันใหม่ใช้บริบทของวันใหม่ ไม่สืบต่อเอง ไม่เปลี่ยนเป้าหมายอาหารหรือแนะนำการชดเชย

## 7. Fitness — ทำและบันทึกการออกกำลัง

```mermaid
flowchart TD
  A([Home → Fitness]) --> B[เลือกโปรแกรมหรือรายการตามตาราง]
  B --> C[ตรวจและปรับท่า เซต และจำนวนครั้ง]
  C --> D[เริ่มออกกำลัง]
  D --> E[บันทึกเซตและพัก]
  E --> F{ทำต่อ?}
  F -->|ต่อ| E
  F -->|จบ| G[ตรวจสรุปการออกกำลัง]
  G --> H{เก็บผล?}
  H -->|เก็บ| I([ประวัติการออกกำลัง])
  H -->|ทิ้ง| J([กลับ Fitness])
```

## 8. Profile — ปรับเป้าหมาย

```mermaid
flowchart TD
  A([Home → Profile]) --> B[เลือกข้อมูลหรือเป้าหมายที่ต้องการแก้]
  B --> C[กรอกค่าใหม่]
  C --> D{ข้อมูลใช้ได้?}
  D -->|ไม่ได้| E[บอกจุดที่ต้องแก้]
  E --> C
  D -->|ได้| F[ตรวจผลก่อนบันทึก]
  F -->|บันทึก| G([แสดงเป้าหมายที่อัปเดต])
  F -->|ยกเลิก| H([กลับ Profile])
```

## ข้อตกลงสำหรับออกแบบหน้าจอต่อ

- ทุก flow มีปุ่มกลับและยกเลิกที่ไม่สร้างรายการอาหารเอง
- ขอสิทธิ์กล้องหรือไมค์เฉพาะเมื่อใช้วิธีนั้น และมีทางเลือกพิมพ์
- จุดยืนยันบันทึกเป็นรูปแบบเดียวกันทุกช่องทาง
- การเลือกเมนูที่จะสั่งไม่เท่ากับการกินแล้ว
- ข้อมูลผิดพลาดต้องแก้ได้โดยไม่ต้องเริ่มทั้ง flow ใหม่
- ยังไม่เพิ่มระบบสมัครสมาชิก การแจ้งเตือน หรือการเชื่อมบริการภายนอกที่ผู้ใช้ไม่ได้เลือก
- ทดสอบกับผู้ใช้: บันทึกมื้อแรก, ไมค์ถูกปฏิเสธ, เมนูอ่านไม่ออก, สัปดาห์ไม่มีข้อมูล, เปลี่ยนบริบทแล้วกลับวันปกติ

## 9. F06 — Library [แบบเสนอใหม่]

เป้าหมาย: ได้คำตอบเกี่ยวกับอาหารเสริมพร้อมเข้าใจข้อจำกัดของข้อมูล รุ่นแรกเน้นความรู้ที่ตรวจทานแล้ว รุ่นตรวจรายการร่วมกันเป็นงานระยะถัดไป

```mermaid
flowchart TD
  A([Home → คลังความรู้]) --> B[ค้นชื่อวิตามินหรือคำถาม]
  C([AI Coach → หัวข้อที่เกี่ยวข้อง]) --> B
  B --> D{มีเนื้อหาที่ตรวจทานแล้ว?}
  D -->|มี| E[อ่านคำตอบสั้นและข้อควรระวัง]
  E --> F[ดูเหตุผล แหล่งข้อมูล และวันที่ทบทวน]
  F --> G([ได้ข้อมูล → บันทึกไว้อ่าน])
  D -->|ไม่มี| H[แจ้งว่ายังไม่มีข้อมูลที่ครอบคลุม]
  H --> I([เตรียมคำถามและรายการไปคุยกับเภสัชกร])
  E -.-> J[ระยะถัดไป · เพิ่มรายการที่ใช้]
  J -.-> K[ยืนยันสารสำคัญ ปริมาณ และข้อมูลยาที่ใช้]
  K -.-> L[แสดงข้อมูลการใช้ร่วมกันและขอบเขตที่ตรวจ]
  L -.-> I
```

ผลตรวจต้องไม่ตีความการไม่พบข้อมูลว่าเป็นการรับรองความปลอดภัย ไม่ปรับยาและอาหารเสริมอัตโนมัติ
